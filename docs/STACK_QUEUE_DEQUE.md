# 스택 · 큐 · 덱

세 자료구조는 "어느 쪽 끝에서 넣고 빼는가"만 다르다. 이 프로젝트에서는 별도 클래스를
만들지 않고 이미 구현한 `DoublyLinkedList`와 `DynamicArray`로 모두 표현한다.

| 구조 | 규칙 | 넣기 | 빼기 | 이 프로젝트의 구현 |
| --- | --- | --- | --- | --- |
| 스택 | LIFO (마지막에 넣은 것이 먼저) | push = 뒤에 추가 | pop = 뒤에서 제거 | `DynamicArray.append` / `pop` |
| 큐 | FIFO (먼저 넣은 것이 먼저) | enqueue = 뒤에 추가 | dequeue = 앞에서 제거 | `DoublyLinkedList.insert_back` / `remove_front` |
| 덱 | 양쪽 끝 모두 가능 | 앞·뒤 추가 | 앞·뒤 제거 | `DoublyLinkedList`의 4개 연산 전체 |

## 스택 (Stack)

접시 쌓기처럼 가장 위(마지막)에만 접근한다. 함수 호출 스택, 되돌리기(undo), 괄호 짝 검사,
깊이 우선 탐색(DFS)이 대표적인 예다.

배열 끝에서만 추가·삭제하면 다른 원소를 옮길 필요가 없으므로 `DynamicArray`가 잘 맞는다.
`append`는 용량이 찰 때만 2배 크기로 복사하므로 분할 상환(amortized) O(1)이고, `pop`은 O(1)이다.
반대로 배열 앞에서 삭제하면 나머지를 한 칸씩 당겨야 해 O(n)이 된다. 그래서 배열은 스택에는
적합하지만 큐에는 적합하지 않다.

`BinaryTree`의 전위·중위·후위 순회는 재귀로 구현했다. 재귀는 Python의 호출 스택을
암묵적인 스택으로 쓰는 것이다. 트리가 한쪽으로 치우쳐 깊이가 매우 크면 재귀 한도에 걸릴 수 있다.

## 큐 (Queue)

줄 서기처럼 먼저 온 것이 먼저 나간다. 작업 대기열, 메시지 버퍼, 너비 우선 탐색(BFS)에 쓴다.

이중 연결 리스트는 `head`와 `tail`을 모두 알고 있으므로 뒤에 넣고(`insert_back`) 앞에서
빼는(`remove_front`) 연산이 모두 포인터 몇 개만 바꾸는 O(1)이다.

프로젝트 내 사용처:

- **Pub/Sub 구독자 버퍼** (`pubsub.py`): `PUBLISH`가 구독자마다 `inbox.insert_back`으로
  메시지를 쌓고, `drain()`이 `remove_front`로 도착 순서대로 꺼낸다.
- **레벨 순회** (`binary_tree.py`): 루트를 큐에 넣고, 하나 꺼낼 때마다 자식을 뒤에 넣는다.
  먼저 들어간 얕은 층의 노드가 먼저 처리되므로 결과가 층별 순서가 된다.

## 덱 (Deque, Double-Ended Queue)

양쪽 끝에서 모두 넣고 뺄 수 있어 스택과 큐를 모두 대신할 수 있다. 슬라이딩 윈도우 최댓값,
작업 훔치기(work stealing), 캐시 교체 정책 등에 쓴다.

`DoublyLinkedList`는 `insert_front`, `insert_back`, `remove_front`, `remove_back`이 모두
O(1)이므로 그 자체로 덱이다. 여기에 "임의의 노드를 O(1)에 빼서 앞으로 옮기는"
`move_to_front`를 더한 것이 LRU 목록이다.

- 성공한 `SET`·`GET`: 노드를 앞으로 이동 (`move_to_front`, 새 키는 `insert_front`)
- LRU 퇴출: 가장 오래 사용되지 않은 뒤쪽 키 선택 (`tail`) 후 제거

즉 LRU 캐시는 "해시맵으로 노드를 바로 찾는 덱"이라고 볼 수 있다.

## 정리

| 연산 | 동적 배열 | 이중 연결 리스트 |
| --- | --- | --- |
| 뒤에 추가 | 분할 상환 O(1) | O(1) |
| 뒤에서 제거 | O(1) | O(1) |
| 앞에 추가 / 앞에서 제거 | O(n) | O(1) |
| 인덱스로 접근 | O(1) | O(n) |

인덱스 접근이 필요하고 끝에서만 바뀌면 배열(스택, 힙 저장소), 양쪽 끝이나 중간 노드를
자주 바꾸면 연결 리스트(큐, 덱, LRU, 해시 체인)를 선택한다.
