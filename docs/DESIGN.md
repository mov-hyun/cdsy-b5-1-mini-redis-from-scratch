# 구현 구조와 동작 원리

## 키를 찾는 과정

`HashMap`은 키의 UTF-8 바이트를 순서대로 읽으며
`h = (h * 31 + byte) & 0xFFFFFFFF`를 계산한다. 31을 곱하면 바이트의
순서가 결과에 반영되고, 마스크는 정수 크기를 32비트로 제한한다.
최종 해시를 버킷 수로 나눈 나머지가 저장 위치다. 암호학적 해시가 아니다.

서로 다른 키가 같은 버킷에 들어오면 이중 연결 리스트에 함께 저장하고
원래 키를 비교한다. 키 수 / 버킷 수가 0.75를 초과하면 버킷 수를 두 배로
늘리고 모든 엔트리의 위치를 다시 계산한다. 기존 키 덮어쓰기는 개수를 늘리지 않는다.

## LRU를 빠르게 갱신하는 방법

저장소와 별도로 `lru_nodes` 해시맵이 키에 해당하는 연결 리스트 노드를 보관한다.
따라서 목록을 처음부터 검색할 필요 없이 노드를 찾는다. 성공한 SET·GET은
노드를 맨 앞으로 옮기고, 퇴출할 때는 맨 뒤의 키를 선택한다.
이동은 앞뒤 포인터 몇 개만 바꾸므로 목록 길이에 관계없이 O(1)이다.
해시맵 탐색까지 포함하면 평균 O(1)이며 충돌이 집중되면 느려질 수 있다.

예를 들어 SET a, SET b, GET a를 실행하면 앞에서부터 a → b가 된다.
여기에 c를 저장하며 제한을 넘으면 가장 오래 사용하지 않은 b를 제거한다.
EXISTS·TTL·EXPIRE는 접근 순서를 바꾸지 않는다.

## 메모리 제한과 삭제

`used_memory`는 UTF-8로 인코딩한 키와 값 길이의 합이다. 한글 '키'와 '값'은
각각 3바이트이므로 합계 6바이트다. 실제 Python 프로세스 메모리와 다르며
버킷, 노드, TTL 기록의 오버헤드는 과제 정의에 따라 제외한다.

SET은 먼저 단일 엔트리가 제한에 들어가는지 확인한다. 들어가지 않으면 OOM이다.
저장할 수 있으면 이전 크기를 빼고 새 크기를 더한 뒤 LRU를 갱신한다.
전체 사용량이 제한 이하가 될 때까지 맨 뒤 키를 삭제하고 퇴출 수를 누적한다.
DEL·만료·퇴출은 `_remove_key`를 공유해 데이터, 노드 맵, 목록, TTL 메타데이터와
사용량을 함께 갱신한다. 만료와 DEL은 `evicted_keys`에 포함하지 않는다.

## 가장 이른 만료 찾기

최소 힙은 부모가 자식보다 작거나 같은 완전 이진 트리를 배열로 표현한다.
인덱스 i의 부모는 `(i-1)//2`, 자식은 `2*i+1`, `2*i+2`다.
삽입은 끝에 넣고 부모와 비교하며 올라가고, 삭제는 마지막 항목을 루트로
옮긴 뒤 더 작은 자식과 교환하며 내려간다. 루트에서 가장 이른 만료를 바로 확인한다.

힙 항목은 `(만료시각, 키, 버전)`이다. EXPIRE를 다시 설정하면 버전을 증가시키고
새 항목을 넣는다. 맨 위 항목이 현재 TTL 메타데이터와 다르면 버린다.
이 방식은 삭제 후 동일한 키를 재생성해도 이전 기록이 새 값을 삭제하지 않게 한다.
예: a의 1초 만료를 3초로 변경하면 1초 기록은 무효이고 3초 기록만 유효하다.

각 명령 시작에 시계를 한 번 읽고 만료를 정리한다. 경계 시각과 같으면 만료다.
TTL의 남은 초는 내림하며, 1초 미만이면 0이다. 테스트는 가짜 나노초 시계를
주입하므로 실제로 수 초를 기다리지 않고 경계 조건을 재현한다.

## 비용과 한계

키 길이를 고정해 생각할 때 해시맵 조회는 평균 O(1), 최악 O(n)이다.
실제로는 키 해시에 UTF-8 바이트 수만큼 시간이 든다. 재배치는 전체 키를 읽는다.
KEYS는 O(버킷 수 + 키 수)이고, 힙 삽입·삭제는 O(log h), peek는 O(1)이다.
h는 무효 기록을 포함한 힙 크기다. 한 명령에서 만료가 여러 개 발생하면
그 개수만큼 정리 비용이 추가되므로 모든 GET을 항상 O(1)이라고 할 수 없다.

힙 내부 list는 배열 저장소와 끝 삽입·삭제에만 사용한다. 해시맵 버킷도
고정 길이 list를 사용하며 내장 Key-Value 컬렉션으로 탐색을 대체하지 않는다.
동적 배열 자체 구현은 선택 과제로 남겼다.

네트워크, 파일 영속성, 복합 자료형, 동시성 및 선택 보너스는 구현하지 않았다.
입력 대기 중에는 만료 청소가 실행되지 않는다. 긴 만료를 반복 설정하면
무효 힙 기록이 남을 수 있다. 정수는 Python int 범위를 사용하며 실제 Redis의
모든 상한과 프로토콜을 복제하지 않는다. 입력 파서는 shlex의 인용·역슬래시
규칙을 사용하므로 역슬래시를 포함하는 문자열은 따옴표와 이스케이프에 주의한다.
